# 학업여지도 PRD
## Product Requirements Document v1.0

- **문서 버전**: 1.0
- **작성일**: 2026년 10월 26일
- **서비스**: 학업여지도
- **서비스 URL**: [https://leamap.kr/](https://leamap.kr/) (별칭: [https://leamap.vercel.app/](https://leamap.vercel.app/))
- **제품 유형**: 교육환경 탐색 플랫폼 및 사업자 대상 구독형 SaaS
- **핵심 수익원**: 학원 프리미엄 구독, 부동산 지역 홍보 구독, 향후 지역 분석 구독
- **개발 원칙**: 기존 서비스 재사용, 1인 운영 최적화, 빠른 유료화 검증

## 1. 제품 개요

### 1.1 제품 비전
- 학부모에게는 학교·학원·지역 정보를 무료로 탐색할 수 있는 서비스를 제공하고, 학원과 부동산 중개사무소에는 지역 내 잠재 고객에게 도달할 수 있는 마케팅 도구를 제공한다.
- 장기적으로는 지역별 교육환경 정보를 기반으로 학원과 부동산 사업자가 시장을 분석하고 영업 기회를 찾을 수 있는 플랫폼으로 발전시킨다.

### 1.2 제품 목표

#### 사업 목표
- 학부모용 주요 탐색 기능을 무료로 제공한다.
- 학원이 직접 정보를 관리하고 프리미엄 노출을 구매할 수 있도록 한다.
- 부동산 중개사무소가 지역 소개 페이지와 홍보 상품을 구매할 수 있도록 한다.
- 사업자 구독 매출을 확보하고 월 반복매출 500만원을 장기 목표로 설정한다.

#### 제품 목표
- 학부모가 학교·학원·지역 정보를 쉽게 탐색할 수 있어야 한다.
- 사업자가 직접 프로필을 등록하고 관리할 수 있어야 한다.
- 관리자가 광고와 사업자 정보를 쉽게 검수할 수 있어야 한다.
- 프리미엄 상품의 결제 및 구독 상태를 확인할 수 있어야 한다.
- 광고 노출과 상담 클릭 성과를 측정할 수 있어야 한다.

### 1.3 핵심 성공 가설
| 가설 | 검증 방법 |
| :--- | :--- |
| 학부모는 무료 교육환경 탐색 서비스를 이용한다 | 방문자·검색·상세 조회 측정 |
| 학원은 지역 내 노출에 비용을 지불한다 | 실제 유료 전환 확인 |
| 학원은 상담 문의 성과를 중요하게 생각한다 | 상담 클릭과 유효 문의 측정 |
| 부동산은 교육환경 중심 홍보에 비용을 지불한다 | 지역 페이지 시범 운영 및 결제 검증 |
| 사업자는 매월 반복적으로 서비스를 이용한다 | 구독 갱신 및 해지율 측정 |

> [!NOTE]
> 위 가설은 검증 전이며, 실제 결제 데이터에 따라 제품 우선순위를 변경한다.

## 2. 제품 원칙

### 2.1 학부모 무료 이용
- 학교·학원·지역 검색, 기본 정보 열람, 지도 탐색 및 비교 기능은 무료로 제공한다.
- 학부모가 기본 정보를 확인하기 위해 결제하도록 유도하지 않는다.

### 2.2 광고와 일반 정보 분리
- 유료 광고는 일반 검색 결과와 시각적으로 구분한다.
- 프리미엄 상품을 구매한 학원이 교육적으로 더 우수하거나 성적 향상 효과가 더 크다는 인상을 주지 않도록 한다.

### 2.3 데이터 신뢰성 우선
- 데이터 출처와 기준일을 표시한다.
- 확보 권한이 불분명한 데이터는 사용하지 않는다.
- 자동 수집 가능 여부와 별개로 데이터 이용 조건을 확인한다.
- 검증되지 않은 학업성취도나 학교폭력 정보는 핵심 서비스에 포함하지 않는다.

### 2.4 1인 운영 최적화
- 사업자가 직접 정보를 수정하고 상품을 신청할 수 있도록 하며, 관리자가 반복적으로 처리해야 하는 작업을 최소화한다.

### 2.5 단계별 개발
- MVP에서는 학원 프리미엄 상품을 우선 출시한다. 부동산 홍보 상품과 지역 분석 도구는 데이터와 고객 수요가 검증된 뒤 확장한다.

## 6. 기능 요구사항

### 6.1 P-01. 학부모 무료 탐색 (P0)
- **목적**: 학부모가 무료로 학교·학원·지역 정보를 탐색하게 한다.
- **요구사항**:
  - 기존 검색 및 지도 기능을 유지한다.
  - 학교와 학원의 상세 페이지를 제공한다.
  - 기본적인 학교·지역 비교 기능을 제공한다.
  - 공개된 정보에 출처와 기준일을 표시한다.
  - 프리미엄 광고는 일반 정보와 구분한다.
  - 상담 버튼은 해당 사업자의 연락처 또는 문의 화면으로 연결한다.
- **검수 기준**:
  - 비회원도 공개 정보 열람이 가능해야 한다.
  - 기본 탐색 기능 이용 시 결제를 요구하지 않아야 한다.
  - 광고 콘텐츠에는 광고임을 식별할 수 있는 표시가 있어야 한다.
  - 없는 데이터나 확인되지 않은 정보를 임의로 생성하지 않아야 한다.

### 6.2 P-02. 학원 상세 프로필 (P0)
- **목적**: 학원이 잠재 고객에게 필요한 정보를 제공할 수 있도록 한다.
- **프로필 항목**: 학원명, 주소, 지도 위치, 대표 과목, 대상 학년, 수업 방식, 학원 소개, 연락처, 홈페이지 또는 SNS, 사진, 수강료 정보(선택), 정보 기준일 및 최종 수정일
- **동작 규칙**:
  - 공개 전 관리자 검수 또는 정책 기반 검수를 거친다.
  - 사업자는 본인이 관리 권한을 가진 학원만 수정할 수 있다.
  - 정보 변경 이력을 저장한다.
  - 과장 광고나 허위 실적 신고가 접수되면 관리자가 검토할 수 있어야 한다.
- **검수 기준**:
  - 승인된 학원만 공개 페이지에 노출된다.
  - 사업자는 승인된 학원 정보만 수정할 수 있다.
  - 필수 항목이 누락된 상태에서는 게시 신청을 완료할 수 없다.
  - 관리자 수정 및 승인 이력이 기록된다.

### 6.3 P-03. 사업자 등록 신청 (P0)
- **목적**: 학원 및 부동산 사업자가 스스로 등록을 요청하게 한다.
- **신청 항목**: 사업자 유형, 사업자명, 대표자 또는 담당자명, 연락처, 이메일, 사업장 주소, 관리 대상 학원 또는 중개사무소, 사업자 확인 자료(필요시), 개인정보 처리 동의
- **상태값**:
  - `draft`: 작성 중
  - `submitted`: 승인 대기
  - `approved`: 승인 완료
  - `rejected`: 반려
  - `suspended`: 이용 정지
- **검수 기준**:
  - 중복 신청을 확인할 수 있어야 한다.
  - 승인 전에는 프리미엄 광고를 게시할 수 없어야 한다.
  - 반려 사유를 사업자에게 표시할 수 있어야 한다.
  - 관리자가 사업자 등록 신청을 승인(`approved`) 또는 반려(`rejected`) 처리할 경우, 회원 서비스(메인 마이페이지) 및 파트너센터의 알림 센터에 실시간 알림(승인 축하, 반려 사유 및 재신청 링크)이 Supabase DB `notifications` 테이블에 등록되며 상단 알림 버튼(종 아이콘)에 미확인 알림 뱃지가 즉시 연동 표시된다.
  - 사이트 내 핵심 이벤트(파트너 승인, 신청 반려, 회원가입 완료 환영, 공지사항) 알림을 통합 제공하여 회원이 사이트 내 주요 상태 변화를 즉시 인지할 수 있도록 지원한다.
  - 관리자가 시스템 공지사항을 등록할 때 전체 회원 대상 또는 특정 회원을 선택하여 공지 및 알림을 발송할 수 있으며, 회원 선택 시 모달 회원 리스트에서 회원 유형(학부모/원장·강사/컨설턴트/관리자) 및 가입 경로별 검색을 통해 정밀하게 대상을 지정할 수 있다. 회원 알림 발송 여부를 선택할 수 있으며, 특정 회원 대상 공지는 해당 회원에게만 안전하게 전달되고 다른 회원의 알림함에는 절대 노출되지 않는다.
  - 반려된 사업자가 사업자 등록 정보를 수정·제출하면 단순 '수정되었습니다'가 아닌 '승인 신청하였습니다.' 메시지가 노출되며, 사업자 상태가 승인 대기('submitted')로 재전환되어 관리자 재심사 프로세스로 연동된다.
  - 사업자 권한 부여와 회수는 관리자만 수행할 수 있어야 한다.

### 6.4 P-04. 사업자 대시보드 (P0)
- **목적**: 사업자가 프로필, 상품, 성과를 한 화면에서 관리하게 한다.
- **표시 항목**: 프로필 공개 상태, 프리미엄 구독 상태, 구독 만료 예정일, 프로필 조회 수, 광고 클릭 수, 전화 또는 상담 클릭 수, 최근 문의 내역, 프로필 수정 버튼, 상품 변경 및 결제 버튼
- **검수 기준**:
  - 사업자는 자신의 데이터만 볼 수 있어야 한다.
  - 다른 사업자의 상세 성과 데이터는 조회할 수 없어야 한다.
  - 조회 수와 클릭 수는 정의된 측정 기준에 따라 계산되어야 한다.

### 6.5 P-05. 프리미엄 상품 안내 (P0)
- **목적**: 사업자가 무료 상품과 유료 상품의 차이를 이해하고 구매를 결정하게 한다.
- **학원 상품 구성**:
  | 항목 | 무료 등록 | 프리미엄 (월 29,000원) |
  | :--- | :--- | :--- |
  | 기본 프로필 | 제공 | 제공 |
  | 일반 검색 노출 | 제공 | 제공 |
  | 추가 프로필 정보 | 제한적 | 제공 |
  | 프리미엄 광고 영역 | 미제공 | 제공 |
  | 성과 통계 | 기본 | 확장 |
  | 상담 문의 관리 | 기본 연결 | 확장 기능 |
- **부동산 상품 구성 (P1 후속)**:
  | 항목 | 지역 전문 (월 49,000원) | 교육환경 파트너 (월 99,000원) |
  | :--- | :--- | :--- |
  | 중개사무소 프로필 | 제공 | 제공 |
  | 지역 소개 페이지 | 기본 | 확장 |
  | 프리미엄 노출 | 미제공 | 제공 |
  | 조회·문의 통계 | 기본 | 확장 |
- **검수 기준**:
  - 상품별 가격, 결제 주기, 제공 기능이 명확해야 한다.
  - 가격과 기능을 확인한 후 구매할 수 있어야 한다.
  - 무료 상품과 유료 상품의 차이를 명확히 확인할 수 있어야 한다.
  - 구독 해지 및 환불 정책에 접근할 수 있어야 한다.

### 6.6 P-06. 결제 및 구독 관리 (P0)
- **목적**: 사업자가 프리미엄 상품을 구매하고 구독 상태를 확인하게 한다.
- **요구사항**: 상품 선택, 결제 요청, 결제 결과 확인, 구독 시작일 및 종료일 저장, 구독 상태 표시, 구독 해지 요청, 결제 내역 확인, 결제 실패 상태 관리
- **구독 상태**:
  - `pending`: 결제 대기
  - `active`: 이용 중
  - `past_due`: 결제 실패 또는 미납
  - `cancelled`: 해지 예정 또는 해지 처리
  - `expired`: 이용 기간 종료
  - `refunded`: 환불 완료
- **보안 및 검수 기준**:
  - 브라우저에서 결제 성공 화면이 표시됐다는 이유만으로 구독을 활성화하지 않는다.
  - 서버에서 결제 결과를 검증한다.
  - 결제 결과 통지는 중복 처리되지 않도록 한다.
  - 구독 권한 변경 이력을 기록한다.
  - 결제 실패 시 사업자가 현재 상태와 해결 방법을 확인할 수 있어야 한다.

### 6.7 P-07. 프리미엄 광고 노출 (P0)
- **목적**: 유료 사업자가 추가적인 노출 기회를 얻도록 한다.
- **노출 규칙**:
  - 유료 광고는 '광고' 또는 '스폰서' 등 명확한 표시를 한다.
  - 광고 노출 순위는 결제 여부만으로 학교·학원 품질을 판단하는 방식으로 표현하지 않는다.
  - 광고 상품의 기간이 종료되면 프리미엄 노출을 중단한다.
  - 승인되지 않은 사업자나 정지된 사업자는 광고를 게시할 수 없다.
  - 광고 영역과 일반 검색 결과의 디자인을 구분한다.
- **검수 기준**:
  - 활성 구독 사업자의 광고만 프리미엄 영역에 표시된다.
  - 만료된 광고는 정책에 정해진 시점에 자동으로 중단된다.
  - 일반 정보와 광고 콘텐츠가 시각적으로 구분된다.
  - 노출 및 클릭 기록이 저장된다.

### 6.8 P-08. 조회 및 클릭 통계 (P0)
- **목적**: 사업자가 상품의 효과를 확인할 수 있게 한다.
- **측정 이벤트**:
  - `profile_view`: 상세 프로필 조회
  - `premium_impression`: 광고 노출
  - `phone_click`: 전화 버튼 클릭
  - `contact_click`: 상담 문의 버튼 클릭
  - `website_click`: 홈페이지 이동
  - `inquiry_submitted`: 문의 제출
  - `subscription_started`: 구독 시작
  - `subscription_cancelled`: 구독 해지
- **검수 기준**:
  - 기간별 조회 및 클릭 통계를 확인할 수 있어야 한다.
  - 사업자는 자신의 프로필 성과만 확인할 수 있어야 한다.
  - 집계 기준을 사업자에게 설명할 수 있어야 한다.

### 6.9 P-09. 상담 문의 연결 (P1)
- **목적**: 학부모의 상담 의향을 사업자에게 연결한다.
- **문의 항목**: 문의 대상, 문의 내용, 연락 가능한 방법, 연락처, 개인정보 처리 동의
- **검수 기준**:
  - 문의 제출 전에 개인정보 처리 안내를 확인할 수 있어야 한다.
  - 제3자 제공에 동의하지 않은 문의 정보를 해당 사업자에게 전달하지 않는다.

### 6.10 P-10. 관리자 화면 (P0)
- **목적**: 1인 운영자가 사업자와 광고를 효율적으로 관리한다.
- **필수 기능**: 사업자 신청 목록 및 상세 조회, 승인·반려·정지, 학원·부동산 프로필 검수, 광고 노출 상태 관리, 상품 및 가격 관리, 구독 상태 조회, 결제 내역 조회, 상담 문의 확인

### 6.11 P-15. 아이 주변 교육·문화 자원 지도 (P0)
- **학부모의 질문**: "집 근처에 아이가 공부하거나 체험할 만한 곳이 있을까?"
- **목적**:
  - 도서관, 청소년시설, 공공 체육시설, 과학·문화 체험시설 등 공공 교육자원을 지도에서 찾고 연령대와 관심 분야에 따라 추천한다.
  - 사교육(학원 등)에만 의존하지 않고, 공교육 밖의 건강한 성장 기회를 학부모에게 무료로 제공하여 서비스 신뢰도를 극대화한다.
- **활용 데이터**:
  - 공공도서관 위치 및 운영정보 (휴관일, 도서대출, 열람실, 어린이 자료실 여부)
  - 청소년시설(청소년수련관, 청소년문화의집, 특화시설 등) 위치 및 방과후·동아리 프로그램 정보
  - 공공 체육시설(수영장, 체육관, 축구장 등) 위치 및 유소년 강좌 정보
  - 과학·문화 체험시설(과학관, 박물관, 미술관, 천문대, 생태체험관 등) 위치 및 전시·체험 프로그램 정보
- **확장 기능 (3대 특화 기능)**:
  1. **주말 체험 코스 (Weekend Course)**: 반경 1~3km 내 2~3개 연계 테마 코스 추천 (예: 과학관 체험 + 어린이 도서관 독서 코스)
  2. **방학 활동 계획 (Vacation Plan)**: 방학 동안 알차게 보낼 수 있는 공공시설 주간/월간 체험·학습 플랜 자동 편성
  3. **집에서 가까운 무료 교육시설 추천 (Free Resource Curation)**: 비용 부담 없는 양질의 관공서·공공기관 학습/체험 공간 큐레이션
- **차별점**:
  - 사교육 정보뿐 아니라 공교육 밖의 성장 기회를 함께 제공
  - 지자체 공공 인프라를 활용한 가계 교육비 절감 및 교육격차 해소 기여
- **개발 난이도 및 데이터 검증**:
  - 개발 난이도: 낮음~중간
  - 공공데이터 접근성: 공공데이터포털(data.go.kr), 서울 열린데이터광장(data.seoul.go.kr), 문화포털 OpenAPI 검증 후 정제된 마스터 데이터셋 구축 및 로컬 캐싱 적용
- **검수 기준**:
  - 지도 상에 공공 교육·문화 자원 핀(도서관 📚, 청소년시설 🏛️, 체육시설 ⚽, 과학·문화체험 🔬)이 정상 렌더링되어야 한다.
  - 연령대(유아, 초등 저학년/고학년, 중학생, 고등) 및 관심분야(독서, 과학/IT, 예술, 체육, 역사)에 따른 즉시 필터링이 가능해야 한다.
  - 주말 체험 코스 및 방학 활동 계획 모달/뷰에서 추천 리스트가 올바르게 생성되어야 한다.
  - '무료 시설만 보기' 토글 적용 시 입장료/수강료가 무료인 공공시설만 정밀 선별되어야 한다.

## 10. 테스트 및 인수 기준 (TC-001 ~ TC-015)

1. `TC-001`: 비회원이 학교 및 학원을 검색한다 -> 검색 결과 정상 노출 (무료)
2. `TC-002`: 비회원이 학원 상세 페이지를 연다 -> 공개 정보 정상 노출
3. `TC-003`: 미승인 학원이 프로필 공개를 요청한다 -> 승인 전 공개되지 않음 (`submitted` 대기)
4. `TC-004`: 승인된 학원이 정보를 수정한다 -> 권한 확인 후 수정 내용 저장
5. `TC-005`: 사업자가 다른 사업자의 정보를 수정하려 한다 -> 접근 차단
6. `TC-006`: 학원이 프리미엄 결제를 완료한다 -> 서버 검증 후 구독 활성화 (`active`)
7. `TC-007`: 결제 검증이 실패한다 -> 구독이 활성화되지 않음
8. `TC-008`: 결제 웹훅이 중복 전달된다 -> 중복 활성화 방지
9. `TC-009`: 구독이 만료된다 -> 프리미엄 광고 노출 자동 중단
10. `TC-010`: 비회원이 상담 문의를 제출한다 -> 동의 및 검증 절차에 따라 처리
11. `TC-011`: 동의하지 않은 개인정보가 사업자에게 전달되려 한다 -> 전달 차단
12. `TC-012`: 관리자가 사업자를 정지한다 -> 광고 및 사업자 기능 정책에 따라 중단 (`suspended`)
13. `TC-013`: 광고가 일반 검색 결과에 노출된다 -> 광고 표시가 명확하게 나타남
14. `TC-014`: 사업자가 성과 대시보드를 연다 -> 본인 소유 사업자의 통계만 표시
15. `TC-015`: 광고 클릭이 발생한다 -> 정의된 분석 이벤트 (`premium_ad_click`, `contact_click`) 기록
16. `TC-016`: 학부모가 공공 교육·문화 자원 지도를 탐색한다 -> 도서관·청소년·체육·과학문화 시설의 위치, 운영정보, 연령/관심사별 추천 및 주말 체험 코스/방학 계획/무료 시설이 정상 제공됨

17. `TC-017`: 사업자가 학원 상세 프로필 관리에서 '학원소개', 학원 로고(썸네일), 학원 강의실/전경 사진(최대 10장)을 등록/수정/삭제한다 -> 업로드된 이미지가 즉시 저장되고 신뢰 지수에 가산되며, 새로고침 시에도 정상 복원됨
18. `TC-018`: 사업자가 등록된 학원 로고 또는 학원 시설 사진을 개별/전체 삭제한다 -> 확인 팝업 후 즉시 미리보기 및 그리드에서 제거되고, 서버의 실제 파일 정리 API(`/api/business/delete-image`)가 호출되며 프로필 저장 시 삭제된 상태가 유지됨

### 10.8 Vercel 서버리스 환경 관리자 블로그 이미지 업로드 및 노출 지원 (2026-11-05 업데이트)
- **원인**: Vercel 서버리스 환경(`leamap.vercel.app`)은 런타임 파일시스템이 읽기 전용(`EROFS`)이어서 `public/uploads/blog` 디렉토리 생성·쓰기 시 500 오류가 발생하고, 대용량 원본 이미지 전송 시 4.5MB 페이로드 제한에 걸리는 문제가 있었음. 또한 `blog_posts` 테이블에 별도 에셋 행(`is_published: false`)을 저장하면 구버전 운영 화면에서 임시저장 게시글처럼 노출되는 부작용이 있었음.
- **해결**:
  1. 클라이언트(`admin.js`)에서 업로드 전 고해상도 이미지를 자동 리사이즈·최적화(`compressBlogImageIfNeeded`)하여 전송 용량 초과를 방지함.
  2. 서버(`server.js` `/api/admin/blog/upload-image`)에서 별도의 `blog_posts` 행을 생성하지 않고 `dataUrl`과 메모리 캐시를 반환하며, 게시글 저장 시 해당 게시글의 `blog_posts.images` JSONB 컬럼 내부에 `{ url, filename, name, size, dataUrl }` 형태로 영구 저장되도록 개선함.
  3. `/api/blog/image/:filename` 및 `/uploads/blog/:filename` 엔드포인트(`vercel.json` 리라이트 포함)가 메모리 캐시 및 `blog_posts.images` JSONB 내 `dataUrl`을 찾아 스트리밍 응답하고, `blog.js`/`admin.js`에서도 `post.images`의 `dataUrl`을 우선 매핑하여 어디서든 이미지가 즉시 노출되도록 개선함.


### 10.9 프리미엄 학원 광고 — 타깃 학교 1곳 선택 + 학교당 최대 3구좌 제한 + 확장 옵션 (2026-11-05 업데이트)

  - 학부모가 메인 지도에서 **선택된 타깃 학교 핀을 클릭했을 때만** 최상단 `[광고]` 배지 및 우선 정렬이 적용되며, 선택하지 않은 다른 학교 핀을 클릭했을 때는 일반 학원으로 노출됨.

### 10.31 학교 교육환경 종합 지표 및 랭킹 점수 산출 기준 단일화 (2026-11-23 업데이트)
- **개요 및 배경**:
  - 동일한 학교(예: 대치중학교)가 지도 상세 패널에서는 '교육환경 종합 지표 46점'으로 노출되고, 정적 랭킹 페이지(`/rank/seoul-middle-gangnam.html`)에서는 '종합점수 64.4점·강남구 22위'로 불일치하게 표시되던 문제 해결.
- **원인 분석**:
  1. **지도 패널 (기존)**: 필터 슬라이더용 간이 계산식에 의존하여 학폭 발생건수(7건 × 12 = 84점 감점) 및 학급규모(29명 × 2.8 = 81.2점 감점)가 100명당 비율이나 적정 인원 편차 정규화 없이 극단적으로 감점되어 `46점`으로 왜곡 표출됨.
  2. **순위 페이지 (기존)**: 정규화된 100점 만점 공식 배점 체계(학업 40점 + 학급규모 30점 + 학폭안전 20점 + 창체예산 10점)를 사용하여 `64.4점`으로 계산됨.
- **단일 산출 기준 통일 (`calculateSchoolCompositeScore`)**:
  - 두 화면의 개념이 '교육환경 종합 평가'로 동일하므로, 단일 공식 산출 함수로 산출식을 일원화함.
  - **100점 만점 산출 공식**:
    1. **학업 성취도 지표 (40점 만점, 40%)**: `(국영수 3과목 성취도 평균 / 100) * 40`
    2. **교원/학급 규모 지표 (30점 만점, 30%)**: 서울 적정 학급 인원 22명 기준 편차 반영 `Math.max(0, 30 - Math.abs((class_avg_size || 25) - 22) * 2)`
    3. **학교폭력 안전 지표 (20점 만점, 20%)**: 전교생 대비 100명당 발생건수 반영 `Math.max(0, 20 - per_100 * 8)`
    4. **창체활동 지원 예산 (10점 만점, 10%)**: 학생 1인당 200만원 기준 `Math.min(10, (extraBudget / 200) * 10)`
  - **동기화 범위**:
    - 지도 상세 패널 상단 히어로 배너 점수(`totalEnvScoreLabel`), 필터 바 슬라이더 가중치 연동, 사이드바 학교 리스트 종합 정렬 탭, 학교 비교 모달, 순위 페이지(`scripts/generate_rank_pages.js`) 79개 전체 동기화 완료.
    - 대치중학교 기준: 패널 **64.4점** = 순위 페이지 **64.4점** (오차 0.00%, 완벽 일치).

### [시스템 인프라] 공개 읽기 API Vercel 엣지 캐시 및 보안 캐시 정책

#### 1. 도입 배경 및 목적
- **Vercel Serverless Function 호출 절감**: 하루 방문자 대비 반복적인 크롤러/모니터링 조회로 인한 서버리스 실행 시간(Execution Duration) 및 리소스 낭비 차단.
- **반복 요청 흡수**: Vercel Edge Network(CDN 엣지 캐시)가 정적/공개 데이터를 직접 응답하여 응답 속도 향상 및 서버리스 인보케이션 급감 유도.

#### 2. 엔드포인트별 Cache-Control 정책
1. **불변/장기 정적 데이터 (s-maxage: 1일~7일)**
   - `/api/schools`, `/api/config/map-key`, `/api/schoolinfo/violence`, `/api/school-zones/lookup`:
     `Cache-Control: public, max-age=3600, s-maxage=86400, stale-while-revalidate=604800`
   - `/api/crime-zones`, `/api/accident-statistics`, `/api/traffic-accidents`:
     `Cache-Control: public, max-age=86400, s-maxage=604800, stale-while-revalidate=86400`
2. **지역/주택/학원 검색 및 공공데이터 (s-maxage: 1시간)**
   - `/api/realestate/regions`, `/api/realestate/region/:code`, `/api/realestate`, `/api/realestate/pins`:
     `Cache-Control: public, max-age=600, s-maxage=3600, stale-while-revalidate=86400`
   - `/api/academies/count`, `/api/academies/search`, `/api/academies/fees`, `/api/neis/school-search`, `/api/neis/meals`, `/api/neis/schedule`:
     `Cache-Control: public, max-age=300~600, s-maxage=3600, stale-while-revalidate=86400`
3. **파트너/광고/평점 (s-maxage: 30분)**
   - `/api/academies/premium`, `/api/academies/partners`, `/api/real-estates/partners`, `/api/academies/ratings`:
     `Cache-Control: public, max-age=300, s-maxage=1800, stale-while-revalidate=86400`
4. **블로그 및 리뷰 데이터 (즉각 반영 및 짧은 엣지 캐시)**
   - `/api/blog/posts` (일반 공개 조회): `public, max-age=10, s-maxage=60, stale-while-revalidate=300` (새 글 발행 시 1분 내 자동 갱신)
   - `/api/blog/posts` (관리자 조회, `?admin=true`): `no-store, no-cache, must-revalidate` (즉시 최신 상태 반영)
   - `/api/blog/posts/:id`: `public, max-age=60, s-maxage=600, stale-while-revalidate=1800`
   - `/api/reviews`: `public, max-age=10, s-maxage=60, stale-while-revalidate=300`
   - `/uploads/blog/:filename`: `public, max-age=31536000, immutable` (정적 파일 CDN 직행)
   - `/api/blog/image/:filename`: `301 Moved Permanently` ➔ `/uploads/blog/:filename` (리다이렉트 영구 캐시)

#### 3. 캐시 절대 적용 제외 대상 (보안 및 데이터 일관성)
- **관리자/비즈니스 전역 미들웨어 방어**: `/api/admin/*`, `/api/business/*`는 서버 상단 전역 미들웨어에서 `no-store, no-cache, must-revalidate, proxy-revalidate`를 기본 강제 주입하여 어떤 경우에도 엣지/브라우저 캐시되지 않도록 보장.
- **블로그 CUD(생성/수정/삭제) 및 문의/리뷰 쓰기 API**: `POST`, `PUT`, `DELETE` 요청은 일체 캐시 대상에서 제외.
- **개인별/세션 데이터**: 알림(`/api/notifications`), 문의 조회 등 개인화 데이터는 캐시 제외.

### [서버리스 성능 최적화] 대용량 JSON 데이터 지연 로딩(Lazy Loading) 및 냉시동(Cold Start) 단축
- **배경**:
  - `schools_seoul.json`(19.8MB), `src/data/realestate/*.json`(96개 지역 분할 총 360MB) 등 대용량 데이터가 포함된 환경에서, 서버 시작 시점에 전체를 읽거나 매 요청마다 20MB 디스크 I/O를 반복하여 냉시동 및 CPU 낭비 발생.
- **최적화 내역**:
  1. **시작 시점 360MB 사전 로딩 제거**:
     - 서버 시작 시점(`app.listen`)에서 백그라운드로 96개 시군구 360MB 주택 데이터를 일괄 파싱하던 타이머를 전면 제거하여 **서버 모듈 냉시동 시간을 기존 4,000ms+에서 160ms로 약 96% 단축**.
  2. **학교 데이터(`schools_seoul.json`, 19.8MB) 싱글톤 지연 로딩 & 원본 스트링 캐시**:
     - 시작 시점이 아니라 학교 관련 API(`/api/schools`, 학교폭력 공시, 통학구역 배정교 조회 등)가 처음 요청될 때만 1회 온디맨드로 로드(`getSchoolsData()`).
     - 파일 수정 시간(`stat.mtimeMs`) 기반 스마트 캐시를 구축하여 동일 프로세스 내 중복 디스크 I/O 완전 제거.
     - `/api/schools`는 메모리 상의 원본 JSON 문자열을 직접 전송(`res.send(rawStr)`)하여 20MB 파싱 및 직렬화(JSON.stringify) CPU 오버헤드를 0%로 제거.
  3. **데이터 크기별 처리 구분**:
     - **대용량 데이터(Heavy, >1MB)**: `schools_seoul.json`(20MB), `realestate/*.json`(360MB) ➔ 시작 시 로드 금지, 필요한 시점에만 온디맨드 단일 로드 및 메모리 캐시 재사용.
     - **자주 쓰는 경량 데이터(Light, <100KB)**: `config.json`(476B), `businesses.json`(5.5KB), `users.json`(2.7KB), `realestate_regions.json`(6.5KB) 등은 온디맨드 즉시 읽기.
